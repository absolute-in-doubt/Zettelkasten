# Generated classes - JOOQ


При запуске Generator jOOQ анализирует структуру базы данных и создает строковые Java-классы, которые повторяют схему БД. Это позволяет писать типобезопасные запросы и мапить результаты.

  

Все сгенерированные сущности можно разделить на две большие группы: **абстракции структуры базы данных** (таблицы, поля, схемы) и **модели данных (Record-классы)**. Рассмотрим их раздельно.

  

### Часть 1. Классы абстракций базы данных (Tables, Fields, Schemas и др.)

Эти классы описывают **статическую структуру** вашей базы данных. Они не хранят данные конкретных строк, а служат метаданными для построения DSL-запросов (SQL-конструкций).

  

#### 1. Основные виды классов-абстракций:

- **Каталоги и Схемы (`Catalog`, `Schema`):** Корневые контейнеры (актуально для баз данных, где используется разделение на несколько схем или каталогов, например, в PostgreSQL).
    
      
    
- **Таблицы (`Table`):** Классы, представляющие таблицы базы данных (например, `Book`, `Author`). Обычно они реализуются как синглтоны, и к ним обращаются через статические экземпляры (например, класс `Tables` или статические поля в пакете таблицы).
    
      
    
- **Поля / Колонки (`Field<T>`):** Поля таблиц (например, `Book.TITLE`, `Book.ID`). Имеют строгую типизацию (`Field<String>`, `Field<Integer>`), что защищает от ошибок на этапе компиляции.
    
      
    
- **Ключи и Ограничения (`UniqueKey`, `ForeignKey`):** Описания первичных (`PK`) и внешних (`FK`) ключей, которые jOOQ активно использует для автоматического построения связи в `JOIN` (например, `.on(Book.AUTHOR_ID.eq(Author.ID))` или через метод `.onKey()`).
    
      
    
- **Индексы и Представления (Indexes, Views):** Дополнительные метаданные о материализованных/обычных представлениях и индексах.
    
      
    

#### 2. Как они используются:

Эти классы задействованы исключительно при **построении логики запроса** (в DSL-цепочках). Компилятор проверяет типы данных именно благодаря им.

  

_Пример использования:_
  
```java
// Здесь BOOK, TITLE, AUTHOR_ID — это статические объекты-абстракции
Result<Record2<String, Integer>> result = dsl.select(BOOK.TITLE, BOOK.AUTHOR_ID)
    .from(BOOK)                               // Использование класса таблицы
    .where(BOOK.PAGES.greaterThan(300))       // Использование объекта поля с типизированным условием
    .fetch();
```

### Часть 2. Классы записей (Record Classes)

В отличие от метаданных, **Record-классы** представляют собой **актуальные данные конкретных строк** (строки таблиц, результатов JOIN-запросов или хранимых процедур). Они хранят значения полей и позволяют их читать или изменять.

  
#### 1. Основные виды Record-классов:

- **TableRecord (например, `BookRecord`):**
    
      
    - Сгенерированный класс для конкретной таблицы.
        
          
        
    - Содержит геттеры и сеттеры для каждого поля таблицы (`getTitle()`, `setTitle()`, `getId()`, и т.д.).
        
          
        
    - Обладает **активной записью (Active Record)**: такой объект «знает» о своем состоянии и о подключении к БД, что позволяет вызывать методы `.store()` (вставить или обновить), `.update()` или `.delete()` прямо на экземпляре записи.
    
       
    
- **Generic Records (`Record1<T>`, `Record2<T1, T2>`, ..., `RecordN`):**
    
      
    - Универсальные классы-кортежи ( tuples ), которые возвращаются при выборке определенных колонок (например, `select(BOOK.TITLE, AUTHOR.NAME)` вернет `Record2<String, String>`).
        
          
        
    - Позволяют безопасно извлекать данные по индексам (`record.value1()`) или через переданные поля (`record.get(BOOK.TITLE)`).



#### 2. Как они используются:

**А) Чтение данных и маппинг в POJO:**

```java
// Выборка строк в виде типизированных TableRecord
List<BookRecord> books = dsl.selectFrom(BOOK)
    .where(BOOK.PUBLISHED_IN.gt(2020))
    .fetch();

for (BookRecord book : books) {
    String title = book.getTitle(); // Типизированный геттер
    System.out.println(title);
}
```



**Б) Использование Active Record подхода (мутация данных через Record):**

```java
// Создание новой записи через сгенерированный Record-класс
BookRecord newBook = dsl.newRecord(BOOK);
newBook.setTitle("Domain-Driven Design");
newBook.setAuthorId(42);
newBook.store(); // Сгенерирует и выполнит SQL INSERT
```

**В) Превращение в кастомные POJO:**

jOOQ умеет автоматически мапить `Record` на ваши собственные классы (DTO / POJO) по совпадению имен полей и геттеров/сеттеров:


```java
List<BookDto> dtos = dsl.selectFrom(BOOK)
    .fetchInto(BookDto.class); // Автоматический маппинг
```

### Резюме-шпаргалка

|**Аспект**|**Классы абстракций (Tables, Fields)**|**Record-классы (TableRecord, RecordN)**|
|---|---|---|
|**Что это?**|Описание «чертежа» базы данных (карты полей и таблиц).|Конкретные «данные» (строка таблицы или срез полей).|
|**Где применяются?**|Внутри DSL-выражений (`select`, `where`, `join`).|При обработке результатов (`fetch`, маппинг, Active Record).|
|**Изменяемость**|Статические константы/синглтоны.|Мутабельные объекты, хранящие состояние (значения ячеек).|
