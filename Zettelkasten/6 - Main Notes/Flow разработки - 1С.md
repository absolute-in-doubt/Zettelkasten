# Flow разработки - 1С


Обычно параллельно существует две конфигурации - рабочая и тестовая.
В рабочей хранятся пользователи и реальная рабочая информация.
Тестовая нужна для внесения изменений и тестирования их перед выкатом в прод.


> [!note]
> Если у нас много разработчиков - работать постоянно сравнивая кучу .cf файлов неудобно. В этом случае более эффективно использовать [[Хранилище конфигураций - 1С]]

### Перенесение изменений из тестовой коныигурации в рабочую посредством сравнения .cf файлов

Захотели мы добавить справочник. 

Открыли тестовую конфигурацию, добавили справочник, потестили. Видим, что все ок.

После этого жмем "Конфигурация" -> "Сохранить конфигурацию в файл":

![[Pasted image 20260920103355.png|571]]


После этого получаем файл типа "1Сv8.cf"



В рабочей базе жмем "Конфигурация" -> "Сравнить, объединить с конфигурацией из файла":

![[Pasted image 20260920103815.png]]


После этого получаем окно со сравнением конфигураций, где можно развернуть каждый тип объектов вплоть до реквизитов. Например тут, Справочники - Тестовый1 - Свойства - Реквизиты.

Ставим галочки на месте того, что хотим применить (изменения из новой конфигурации)

![[Pasted image 20260920104103.png]]

Жмем "Выполнить" - изменения применяются.
