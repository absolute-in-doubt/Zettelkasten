# JIT, Code cache space - JMM

Java байт код является интерпретируемым и это не настолько быстро как выполнение кода напрямую на целевой платформе. Для увеличения производительности виртуальная машина Oracle Hotspot оценивает наиболее часто используемые части байт кода и компилирует их в код целевой платформы. В дальнейшем этот код хранится в Code Cache в non‑heap памяти. Виртуальная машина Hotspot выбирает наиболее подходящий по времени способ между взятием кода из Code Cache и выполнением интерпретируемого кода.


### Code Cache 

Используется для хранения naitive кода наиболее часто используемых методов.


---
### Виды JIT Compiler


- **C1 (Client Compiler)** — быстрый JIT-компилятор, небольшие накладные расходы, делает относительно простые оптимизации.
    
- **C2 (Server Compiler)** — более тяжёлый, но выполняет агрессивные оптимизации: inlining, escape analysis, loop optimizations и т.д.
    
- **Tiered Compilation** — комбинация C1 + C2. Обычно современная JVM работает именно так:
    
    ```text
    Bytecode
        ↓
    Interpreter
        ↓
    C1 → быстрый JIT
        ↓
    C2 → глубокая оптимизация горячего кода
    ```
    

### В современных JDK

Основные варианты:

- **HotSpot C1/C2** — стандартный вариант OpenJDK.
    
- **Graal JIT** — альтернативный высокоуровневый JIT-компилятор; может использоваться как замена C2 в соответствующих конфигурациях JVM.
    

> В HotSpot есть C1 и C2. C1 быстро компилирует код с базовыми оптимизациями, C2 дольше компилирует, но выполняет более глубокие оптимизации. В режиме Tiered Compilation они работают вместе.


### Настройка JIT через JVM args

`-XX:CICompilerCount` - это **количество потоков JIT-компилятора**, которые JVM выделяет для компиляции Java-кода в машинный код.
