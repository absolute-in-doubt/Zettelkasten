# CAP теорема - System Design

![[Pasted image 20260323182123.png]]


### Consistency

All nodes of a distributed system have the same data at the same time.

Данные, изменённые на одном сервисе видны и другим сервисам:
	Запрос на изменение имени пользователя обработал `identity-service-pod-32jkh345`
	и все остальные инстансы должны видеть уже обновлённое имя пользователя
	

> [!warning] Здесь Consistency - не то же самое, что C в ACID:
> Здесь **Consistency** - мера того, насколько хранилище данных отображает все обновления данных. Если БД хранит и отображает пользователю самые последние версии данных -> Highly Consistent DB.
>
>А в ACID Consistency означает:
> *Каждая транзакция переводит базу данных из одного корректного состояния в другое, не нарушая инварианты (CONSTRAINTS) данных.*



### Availability

Ну тут очевидно.

Измеряется в процентах. Цель -> 99,999% availability.

---
### Partition tolerance

**Partition Tolerance (P)** — способность распределённой системы продолжать работу при **сетевом разделении (network partition)**, когда узлы не могут обмениваться данными.

В CAP считается, что в распределённой системе **P практически неизбежна**, поэтому при partition приходится выбирать между **Consistency (C)** и **Availability (A)**.

### Формулировка CAP теоремы

Распределённая система может достичь только два из этих свойств одновременно.


---
#### Пример

- банковская система следует Consistency + Partition Tolerance, даже если обработка каких-то транзакций займёт дольше - важна безопасность -> жертвуем Availability
